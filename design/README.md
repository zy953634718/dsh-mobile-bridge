# DSH Mobile · 手机端重设计（沉浸式原生）— 评审包

本轮目标：**去掉"网页套壳感"**，把 `/m/` 手机壳重做成原生 App 的界面语言，先产出
**可交互高保真 HTML 预览**供用户评审；评审通过后再落地到
`packages/dsh-plugin-mobile-bridge/public/` 并重建 APK。**本目录不修改生产代码、不重建 APK。**

- 预览文件：`design/preview/index.html`（单文件 · 自包含 · 无外部请求 · file:// 或 http 均可打开）
- 自检脚本：`design/verify-preview.mjs`（静态契约）、`design/preview-runtime-test.mjs`（真实内联 JS 的 DOM 运行时冒烟）
- 预览挂载：Lead 会把单文件复制到 `public/design-preview/index.html`，
  评审地址形如 `http://<桌面 IP>:7860/m/design-preview/`

## 快速预览

```powershell
# 方式 1：直接双击 / 用浏览器打开（无需服务器）

# 方式 2：本地静态服务（手机同 Wi-Fi 访问）
```

| # | 屏幕 | 预览要点 | 交互 |
|---|------|---------|------|
| 01 | 配对页 | 品牌 + 6 位 PIN 大圆角输入格 + 自带数字键盘 + 成功动效；扫码（即将支持）/ APK 下载降权入口；安全提示 | 数字键盘 / 物理键盘输入任意 6 位 → 成功动效 → 主界面；支持退格 |

| 04 | 快捷面板 | 底部 sheet：3×2 网格动作 + 连接状态/延迟 + 重连 + 落地映射说明 | Dock「更多」打开；会话列表 / 新会话 / 刷新 / 诊断 / 设置 / 断开连接 |

## 设计理念：沉浸式原生

1. **内容优先**：聊天内容铺满屏幕，只有极薄的玻璃状态胶囊与 Dock 悬浮在内容之上；
   顶栏不再是一条"网页导航栏"。
2. **玻璃层次而非边框堆叠**：`backdrop-filter` 玻璃 + 1px 低对比描边 + 柔和投影，
   深空黑底色上形成"浮层"而非"页面分块"。
3. **单手可达**：配对数字键盘、Dock、输入框都在拇指区；Dock 与输入框保留 8px 安全间距。
4. **克制动效**：slide/fade + 轻微 spring（180–340ms），成功动效只做一次；
   `prefers-reduced-motion` 下全部降级。
5. **安全区**：预览用 `--safe-top/--safe-bottom` 模拟；真机落地继续沿用
   `env(safe-area-inset-*)` 与 APK 的 `--apk-top-inset` 处理。

## 设计 Tokens

| 类别 | Token | 值 |
|------|-------|----|
| 背景 | `--bg` / `--bg-2` | `#070b12` / `#0a101c`（极夜 `#03050a`，幽蓝 `#080b18`） |
| 玻璃 | `--glass` / `--glass-2` | `rgba(15,23,38,.58)` / `rgba(9,14,25,.76)` + `blur(24–30px)` |
| 描边 | `--line` / `--line-strong` | `rgba(148,163,184,.14)` / `.26` |
| 文字 | `--text` / `--text-2` / `--muted` | `#eef2f8` / `#a8b6cc` / `#71809a` |
| 强调色 | `--accent-a` → `--accent-b` | `#2f7bff → #29d3ff`（电光蓝，默认）；青碧 / 紫电 / 森绿可选 |
| 状态色 | success / warning / danger | `#34d399` / `#fbbf24` / `#fb7185` |
| 圆角 | `--radius-lg` / `--radius-md` / `--radius-sm` | `24 / 18 / 14px`（评审面板可 14–28px 实时调） |
| 字号 | `--fs-title/h2/body/sm/xs/cap` | `21 / 18 / 14.5 / 12.5 / 11 / 9.5px` × 字号缩放（90–115%） |
| 间距 | 4 / 8 / 12 / 16 / 20 基准 | 卡片内边距 12–15px，屏幕安全边 12–18px |
| 动效 | `--ease` / `--ease-spring` | `cubic-bezier(.2,.8,.2,1)` / `cubic-bezier(.34,1.56,.64,1)` |

字体栈全部使用系统字体（中文优先 PingFang SC / HarmonyOS Sans / MiSans / 微软雅黑），
预览与真机一致，**不加载任何外部字体**。

## 交互映射（预览 → 真实落地）

| 预览交互 | 真实产品实现 |
|---------|-------------|
| 数字键盘 + PIN 格 | 与现有 `/m/api/pair` 契约一致；6 位自动提交，真实错误/锁定沿用现有逻辑 |
| 状态胶囊（刷新/更多） | 外壳本地动作：刷新 = 重载 iframe；更多 = 快捷面板 |
| Dock「会话」 | 在**真实 GUI iframe** 内查找并点击 `button[aria-label="打开侧边栏"]` / `"收起侧边栏"`（英文：`Open sidebar` / `Collapse sidebar`，此选择器已在前版 ui-smoke 中验证） |
| Dock「新建」 | 点击真实 GUI 的 `button[aria-label="新建会话"]`（英文：`New session`） |
| Dock「刷新 / 更多」 | 外壳本地动作（重载 iframe / 打开快捷面板），不触碰 GUI 内部状态 |
| 会话抽屉列表 | 真实落地为本地抽屉；"切换会话"需通过 GUI 内对应会话行点击（具体选择器落地时再对齐，预览不假装已实现） |
| 快捷面板动作 | 同 Dock 映射；诊断/设置/断开为外壳本地动作 |
| 设置页服务器地址 | 真实落地显示当前 `location.origin`/host；编辑能力保留在桌面配对页（不在手机端改服务器） |
| 主题/强调色/字号 | 右侧评审面板变量仅为评审用；生产落地默认「深空 · 电光蓝 · 100%」，不新增用户设置项（如需可后续再加） |
| 聊天内容区 | **真实 DSH GUI iframe**（不重写聊天 UI，功能与数据完全保留） |

## 与当前线上壳（v0.2.0）的差异

| 区域 | 当前线上壳 | 本次设计 |
|------|-----------|---------|
| 顶栏 | 40px 紧凑栏 + 自动收起 + 状态胶囊 peek | 仅保留悬浮玻璃状态胶囊，内容区真正全屏；无独立顶栏条 |
| 底部操作 | 悬浮 FAB（展开 4 个动作） | 原生玻璃 Dock（会话/新建/刷新/更多），新建为强调圆形主操作 |
| 会话入口 | 依赖 GUI 自带侧栏轨道 | 新增外壳级会话抽屉（搜索 + 最近会话 + 新建），并保留与 GUI 侧栏的联动 |
| 配对页 | 6 格 PIN + 系统键盘（iOS 易跳变） | 自带数字键盘 + 成功动效 + 扫码/APK 次级入口 |
| 设置/诊断 | 底部诊断抽屉 | 独立设置与诊断页（连接/外观/App/诊断/危险操作分区） |
| 视觉 | 深色 + 蓝青渐变 + 圆角卡片 | 同色系升级：深空黑 + 层叠玻璃 + 更细腻的光晕/噪点/描边/动效 |
| 保留 | PIN/Cookie/代理/APK 全屏/错误处理 | **完全保留**，不进入本次视觉改动 |

## 本次改动范围（重要）

- ✅ **重设计**：外壳、导航（Dock/胶囊）、配对页、会话抽屉、快捷面板、设置/诊断、动效与安全区。
- ✅ **保留**：聊天内容区 = 真实 DSH GUI iframe；PIN 校验 / Cookie 认证 / 反代 / APK 全屏模式。
- 预览里聊天内容是 **mock 示意**（顶部有「示意：生产环境此处为实时 DSH GUI」徽标，右栏也有说明）。
  真实产品中该区域功能、消息、工具调用、输入框全部来自 DSH 本体，本次设计只负责"周围那层壳"。

## 评审清单（重点看这些）

1. 配对流程是否顺手（6 位 PIN + 自带键盘 + 成功动效）
2. 主界面信息密度是否合适（聊天区占比、输入框与 Dock 间距）
3. Dock 的位置与大小是否遮挡内容（尤其 iPhone 底部手势条）
4. 会话抽屉 / 快捷面板的开合手感与遮罩模糊
5. 深色可读性与对比度（正文、次要文字、禁用态）
6. 中文字体与排版（系统字体、行高、数字等宽）
7. 横屏（844×390）是否可用（右侧「横屏」按钮切换）
8. 整体是否"像原生 App"、还有哪里残留套壳感

右侧面板内提供可勾选清单 + 进度条（本机 localStorage 记忆，刷新不丢）。

## 需要用户拍板的点

1. **Dock 四项**是否就是最终导航模型（会话/新建/刷新/更多）？是否需要把"更多"换成"设置"或"搜索"？
2. **会话抽屉**是保留外壳级列表（需与 GUI 会话切换联动），还是仅作为 GUI 侧栏的快捷入口（更轻、落地更快）？
3. **主界面右上角**是否也需要快捷入口（如新会话/设置），还是坚持全部收进 Dock？
4. 视觉基调：默认「深空 · 电光蓝」是否 OK？是否要在生产落地时保留主题/强调色为**用户可选**？
5. 配对页是否需要保留"扫码配对"占位（当前标注"即将支持"），还是首版隐藏？

## 评审通过后的落地步骤（Lead）

1. 按评审结论微调本设计（本目录内迭代，生产代码不动）。
2. 把壳层样式/结构落地到 `packages/dsh-plugin-mobile-bridge/public/`：
   - 保留 DOM/API 契约与现有功能（PIN、隐藏 iframe 登录、401 回退、APK 全屏、代理）；
   - Dock 的会话/新建通过已验证的 `aria-label` 选择器点击真实 GUI；
   - 会话抽屉作为新增外壳能力，按拍板结果决定是否上线。
3. 回归：`public/dev/verify.mjs`、`public/dev/dom-smoke.mjs`、`tests/run-all.ps1` 10/10，
   以及 `public/dev/ui-smoke.mjs` 的 headless Chrome 5 项 UI 检查。
4. 重建签名 APK（`android/` 工具链）→ 真机安装 → 真机配对与全屏模式验证。
